## Surprises & Discoveries

- `docs/developers/basics.md` gave only Meta-internal validation commands (`arc rust-check fbcode//buck2/app/...`, `arc lint`, `arc autocargo`).
- `website/config_impl.ts` publishes every file under `docs/` except `docs/developers/**`, with an autogenerated sidebar, so plans placed in `docs/exec-plans/` would appear on the website.
- `app_dep_graph_rules/rules.bzl` defines crate dependency rules, but `.buckconfig` ignores that directory and its test uses `fbcode//buck2/...` labels, so nothing enforces the rules here. The Cargo graph satisfied them (`cargo metadata --no-deps --format-version 1`, first-party normal dependencies).
- The integration tests under `tests/` load Meta-internal macros through `tests/buck_e2e.bzl`, and `.buckconfig` ignores `tests`, so they cannot run here.
- `docs/developers/basics.md` called the `.elapsed()` ban lint-enforced, but no configuration in this repository enforces it. `app/` has no `.elapsed()` calls.
- Every Cargo command warns that the `bindgen` entry in `[patch.crates-io]` is unused.
- `./bootstrap/yak build //:yak` fails on macOS at `objc2` 0.6.4, which needs `CARGO_PKG_VERSION` at compile time and has no fixup in `shim/third-party/rust/fixups/`.
- `buck2 explain` returns without output outside Meta's build, because `app/buck2_server_commands/src/explain.rs` gates the implementation on `fbcode_build`.
- `app/buck2_daemon/daemon_lifecycle.md` named the lock file `lifecycle.lock`, said `buckd.info` holds a port, and described a version check. The code uses `buckd.lifecycle`, an endpoint with an auth token, and a `DaemonConstraints` check (`app/buck2_client_ctx/src/daemon/client/connect.rs`).
- Nothing in this repository loads `lint_levels.bzl`, and eight crates copy the `[workspace.lints]` table to add a `check-cfg` entry.
- A separate daemon writes its `BUCK_LOG` tracing output to `buckd.stderr` in the daemon directory, and the client writes its own to the terminal.
