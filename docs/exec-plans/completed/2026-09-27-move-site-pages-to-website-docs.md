# Move the documentation site's pages to `website/docs/`

Follows [the plan contract](../../PLANS.md).

## Purpose

The documentation site's pages, its generated reference pages, and the tutorial's example Buck packages live in `website/docs/`, next to the site's configuration and generator.
`docs/` holds only unpublished material (contributor documentation in `docs/developers/`, the plan contract in `docs/PLANS.md`, and plans and the tech-debt tracker in `docs/exec-plans/`), so a file added there stays off the site without an exclude entry.
Page URLs do not change.

## Surprises & Discoveries

- The 2026-09-26 plan says the site has an autogenerated sidebar. `website/sidebars.ts` lists most pages by hand and autogenerates a few sections. Docusaurus still builds a page for every included file, whether or not a sidebar lists it.
- `exclude: ['developers/**']` in `website/config_impl.ts` replaced Docusaurus's default exclude patterns (`_`-prefixed files and directories, `*.test.*` files, and `__tests__/`). No tracked or generated site file matches them, so removing the option leaves the same pages.
- The lab packages failed to load before the move. Their `deps` labels (`fbcode//buck2/docs/buck2_lab/...`) resolve through the `fbcode` alias to the shim cell, which has no `buck2/docs` directory. The lab's `BUCK` files use the prelude's rules, which do not rewrite labels the way the shim's macros do.
- After `git mv docs/buck2_lab website/docs/buck2_lab`, the running daemon still listed the three targets under `//docs/buck2_lab/...` until it restarted. The tech-debt tracker records the cause and a reproduction.
- `docs/.gitignore` ignored `/developers/starlark/`, which nothing has written since commit 03609cbb51 removed `copy_starlark_docs` from `website/gen_docs.py`.

## Context and Orientation

- `website/config_impl.ts` configures the Docusaurus docs plugin. Before this change it read pages from `../docs` and excluded `developers/**`.
- `website/gen_docs.py` runs a built `buck2` to write the API reference (`api/`), prelude rule pages (`prelude/`), command help (`users/commands/`), and query function pages (`users/query/`) into the content directory.
- Docusaurus derives each page's document ID and URL from the file's path relative to the content directory. `website/sidebars.ts` names pages by document ID.
- `.github/workflows/upload_buck2.yml` builds the site with `yarn build_prebuilt` in `website/` and deploys it to the `gh-pages` branch on every push to `main`.
- `docs/buck2_lab/` held the tutorial's example Buck packages, which this repository's Buck build loads because `.buckconfig` does not ignore the directory.
- Comments in `app/buck2_build_api/src/build/action_error.rs`, `app/buck2_build_api/src/build/build_report.rs`, `rust-toolchain.toml`, and `tests/e2e/build/test_build_isolated.py` name page paths.

## Idempotence and Recovery

Each step moves or edits files and can be reversed from Git history.
`gen_docs.py` deletes and rewrites its output directories on each run, so it can be repeated. Git ignores its output and `buck-out/`.
